The same working set runs 12–15× faster on the board whose L2 holds it

A GPU's memory is a ladder: per-SM registers and L1/shared, then one device-wide L2 cache, then DRAM behind a single controller. Latency rises and bandwidth falls as you descend, but capacity rises. Slide a kernel's footprint and watch which level holds it, the bandwidth and latency it then sees, and the time to touch it once. The cliffs sit exactly at 4 MB (Orin) and 32 MB (Thor) — that is where capacity, not datasheet TOPS, decides speed (notes 05, 06; metrics-kit A.6/A.7).

Why capacity beats bandwidth. L2-resident streaming is 12.4× (Orin) / 14.6× (Thor) faster than DRAM, and the cliff is sharp — a footprint just past L2 capacity pays the full DRAM penalty. So a model whose hot set fits Thor's 32 MB L2 but spills Orin's 4 MB runs an order of magnitude faster on Thor at identical advertised TOPS. Note too that Thor's L2 is 8× larger yet about the same latency (146 vs 156 ns) — the win is "more data stays resident", not "resident data is reached faster" (notes 05/06; metrics-kit A.6/A.7).
