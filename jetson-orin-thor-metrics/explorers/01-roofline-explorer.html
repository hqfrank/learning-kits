Roofline explorer: on Orin and Thor, where a kernel lands on the roofline is a memory question, not a TOPS question

A kernel's arithmetic intensity (FLOPs moved per byte moved) decides which ceiling binds it: the sloped memory roof on the left, the flat compute roof on the right. Change the bytes, FLOPs and working-set footprint below and watch which roof binds, which cache level the footprint falls into, and the predicted latency. The π0.5 cases show the measured latency beside the predicted one — the gap is the lesson.

What the sliders mean

Bytes and FLOPs are per inference; their ratio is arithmetic intensity (x-axis). Footprint is the bytes the kernel keeps resident per pass; it decides which cache level serves the traffic, and the explorer streams the bytes at that level's measured bandwidth. The sloped roof uses the bandwidth of the level the footprint lands in (L1 aggregate / L2-resident / DRAM).
