The tunnel survives a Wi-Fi → cellular switch only if the phone migrates before the idle timer runs out

The phone dials one QUIC connection to the cloud and keeps it alive with keepalive PINGs. Each side closes the connection silently after idle timeout seconds without a packet (RFC 9000 §10.1). When the phone changes network, a stack that supports connection migration moves the connection to the new path (RFC 9000 §9); a stack that does not leaves it on the dead path until the idle timer kills it, and then reconnects with backoff. Move the timers and the outage and watch the server's idle timer (notes B2, C2, C3).

An illustrative model, not a measurement. The design timers are illustrative design parameters; the NAT and keepalive guidance is public (RFC 9308, RFC 4787, RFC 8085). When the switch happens and how long the phone has no network are page choices. Round-trip and probe times are ignored except for the reconnect handshake, which counts one round trip plus one for the Retry (B2, C1).
