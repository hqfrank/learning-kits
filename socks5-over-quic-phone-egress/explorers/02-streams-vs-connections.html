QUIC streams combine the two good halves: one handshake like a shared connection, and per-connection loss isolation like separate ones

An agent opens N TCP connections at once (one browser page can open dozens). Three ways to carry them between the cloud and the phone: N separate TCP + TLS 1.3 connections, one shared TCP connection (the WebSocket option of note B2), or one QUIC connection with one stream each (the design). Move the round-trip time, the loss rate and N to see the handshake cost and how many connections one lost packet stalls (notes B2, A1, C2).

An illustrative model, not a measurement. Handshake round trips and loss thresholds are public (RFC 9000, RFC 9001, RFC 8446, RFC 9002); RTTs, loss rates and connection counts are illustrative. The stall length per lost packet is my estimate from the RFC 9002 time threshold plus one round trip for the retransmission. Loss is applied to the cloud-to-phone leg only.
